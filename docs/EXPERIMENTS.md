# Experiment protocol

## Reproducible workflow

Use `python scripts/run_suite.py --steps 1200 --batch-size 32 --seq-len 64 --seeds 11 22 33`. This trains memory and Transformer models per seed, evaluates all requested context lengths, and creates suite-level plots.

## Metrics

- Token-level cross-entropy: primary distribution prediction metric.
- Perplexity: exponential of cross-entropy.
- Next-token accuracy: fraction of correct argmax predictions.
- Memory surprise, write gate and final-state norm: internal memory diagnostics.
- Parameter count, training time and inference throughput: compute/context for interpreting comparisons.

## Sequence-length sweep

Default evaluation lengths: 16, 32, 64, 128, 256, 512, 1024. The Transformer supports up to its configured max context; the recurrent memory carries state sequentially. The same held-out generator seed is used to make comparisons more stable, although a stricter paired-batch evaluation is a future improvement.

## Ablations

1. Retention weight: 0, 1e-5, 1e-4, 1e-3.
2. Memory size: 64, 128, 256.
3. Training sequence length: 32, 64, 128.
4. Model seed: at least three independent seeds.
5. Add regime change points and distractors before evaluating adaptation claims.

## Hypotheses (not results)

- H1: recurrent memory may have a different context-length degradation profile than causal attention.
- H2: surprise-conditioned writes may help after abrupt changes in the latent sequence distribution.
- H3: retention regularization may trade adaptation speed against state stability.

## Plot provenance

Training curves and memory diagnostics are derived from `history.json`. Context-length charts are derived from `evaluation.json`. Token frequencies are counted from actual samples generated by the synthetic task. The sequence-length histogram visualizes the configured sampling protocol, not a measured model result.

## Scientific limitations

This is a small synthetic benchmark, not a natural-language benchmark. The memory mechanism is not an exact Titans reproduction, and the MIRAS-inspired knobs do not constitute a complete MIRAS implementation. A fair architecture claim requires parameter/compute matching, multiple seeds, confidence intervals, and clearly documented data splits.
